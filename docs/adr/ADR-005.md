# ADR-005 — Alocação de Manutenção da Frota

## Contexto

O domínio de Manutenção da Frota contém Telemetria e Manutenção e recebe dados enviados periodicamente pelas bicicletas elétricas.

Este processamento tem um perfil diferente das operações interativas de desbloqueio e devolução. Pretende-se gerir os seus recursos independentemente e limitar o impacto de falhas do respetivo processo no backend principal, mantendo simples a gestão dos dados.

## Decisão

Executar Telemetria e Manutenção no mesmo deploy, separado do backend principal, mantendo uma base de dados partilhada entre ambos.

Utilizar o broker de mensagens para a comunicação assíncrona Telemetria → Manutenção. Quando Telemetria identifica uma avaria, publica uma mensagem para Manutenção, sem aguardar pela criação da ordem de manutenção.

As mensagens são guardadas de forma persistente no broker e confirmadas após o seu processamento.

## Consequências positivas

- Permite atribuir recursos próprios a Manutenção da Frota e ajustar a sua capacidade independentemente do backend principal.
- Permite atualizar e reiniciar este domínio sem reiniciar o backend principal.
- Uma falha do processo de Manutenção da Frota não termina diretamente o processo do backend principal.
- O broker conserva as mensagens de avaria para processamento posterior, mesmo que Manutenção esteja temporariamente indisponível.
- A base de dados partilhada simplifica a administração da persistência, evitando operar bases de dados independentes.

## Consequências negativas

- Acrescenta um deploy para configurar, monitorizar e manter.
- A comunicação através do broker exige tratar falhas e possíveis reentregas, evitando criar ordens duplicadas para o mesmo evento.
- O isolamento é parcial: ambos os deploys partilham os recursos da base de dados e uma falha desta pode afetar ambos.

## Alternativas rejeitadas

### Executar todos os domínios no backend principal

Simplificaria a execução e a operação do sistema. Contudo, o processamento de telemetria partilharia o mesmo processo e os seus recursos com as operações de viagens.

Foi rejeitada para permitir gerir separadamente os recursos de Manutenção da Frota e isolar falhas do respetivo processo.

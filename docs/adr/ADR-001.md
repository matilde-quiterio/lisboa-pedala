# ADR-001 — Acesso aos dados para Reporting Municipal

## Decisão inicial

### Contexto

O sistema deve produzir um relatório mensal para a Câmara com indicadores de utilização por freguesia e CO₂ evitado. Para isso, Relatórios Municipais necessita de consultar os dados das viagens.

### Decisão

Relatórios Municipais obtém os dados através de operações disponibilizadas pelo componente Viagens, sem consultar diretamente as tabelas da base de dados.

### Consequências positivas

- O acesso aos dados fica encapsulado em Viagens.
- Alterações na estrutura das tabelas podem ser realizadas sem afetar Reporting, desde que se mantenha o contrato disponibilizado por Viagens.

### Consequências negativas

- As necessidades de Reporting podem exigir acrescentar ou alterar operações de consulta em Viagens.
- A evolução dos relatórios pode exigir alterações nos dois componentes.

## Revisão da decisão

### Contexto da revisão

Durante a análise dos relatórios, verificou-se que estes necessitam de consultas e agregações específicas. Considerou-se mais adequado concentrar essas operações em Relatórios Municipais, evitando acrescentar a Viagens operações orientadas às necessidades de Reporting.

### Decisão revista

Relatórios Municipais consulta diretamente a base de dados partilhada, apenas em leitura, através de queries definidas no próprio componente. A seleção e agregação dos dados e o cálculo dos indicadores ficam sob a sua responsabilidade.

Esta decisão substitui a decisão inicial e remove a dependência direta Relatórios Municipais → Viagens.

### Consequências positivas

- As consultas e os cálculos específicos dos relatórios ficam concentrados em Relatórios Municipais.
- As queries podem ser adaptadas às necessidades dos relatórios sem alterar a interface de Viagens.
- As agregações podem ser executadas diretamente na base de dados.

### Consequências negativas

- Relatórios Municipais fica dependente da estrutura das tabelas consultadas; alterações podem exigir atualizar as queries.
- As consultas de Reporting partilham recursos da base de dados com as operações do sistema, podendo afetar o seu desempenho. Para reduzir esse impacto, a geração automática mensal é agendada para um período de menor utilização, como o período noturno.
- É necessário garantir que o acesso de Reporting se limita a leitura.

### Alternativa rejeitada

Manter o acesso aos dados através de Viagens. Embora preserve o encapsulamento da persistência, pode exigir adaptar as operações desse componente às necessidades específicas dos relatórios, conforme explicado no contexto da revisão.
